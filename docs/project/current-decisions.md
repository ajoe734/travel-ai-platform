# 目前產品與工程基線

更新：2026-11-22。此檔整理已找回文件及本次接手的實作範圍；不是對過去完成狀態的追認。

## 產品目的

平台代表商家承接接單與營運工作，使用商家現有工具完成詢問、查價查位、預訂接續、售後、服務內容維護及渠道發布。同一組經授權的知識與操作能力，可提供給自有旅客入口及合作渠道。商家不應為了每個正常步驟逐頁操作系統。

依據：[產品規劃 v1.0](../requirements/product-plan-v1.0.md)、[執行角色增補 v1.1](../requirements/execution-role-v1.1.md)、[後續架構整理](../research/2026-11-20-rebuilt-sasd.md)。

## 延續的決策

1. **商家現有工具繼續負責原交易。** 平台負責工作與編排，不重建第二份彼此競爭的訂房、退款或渠道商品主檔。
2. **案件、工作、執行、交易分開。** SA 的 Case 不是客訴的同義詞；後續 Work 表達可驗收責任，不能覆蓋原 Case 或訂單。
3. **知識與正式交易事實分開。** 私有商家資料須有來源、時效、用途與對外授權；正式售價、容量及交易狀態由指定主系統確認。
4. **模型規劃與執行權限分開。** 既有政策可覆蓋的工作自動執行，需要新決策才向對應人員提出清楚選項。
5. **正常流程由系統推進。** 商家看目前等待事項、需做的決定及已確認結果，毋須操作重試、查核等工程步驟。
6. **未知結果先查核。** 對外寫入不因逾時就重做，且各渠道維持自己的發布狀態。
7. **架構完整設計，分段驗收。** 第一個可執行流程可以採 mock；供應商中立核心與不同容量模型仍需保留。
8. **不預設商業條件。** 範例金額、費率、退款門檻與 Credit 額度不構成正式政策。
